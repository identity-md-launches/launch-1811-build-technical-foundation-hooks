# Audit 6b607200 remediation

This change addresses the six low findings in [audit 6b607200-d29f-4c7a-8476-0dca8091f48f](https://github.com/Identity-md/research/blob/main/jobs/6b607200-d29f-4c7a-8476-0dca8091f48f/files/AUDIT.md), against
`0d9d440063465654f39ef7f3939b1b4d9c90c5f6`. No deployment, paid request or fund movement
was performed. No compiler settings, dependencies, token or listing/ad economics changed.

| Finding | Resulting behavior | Adversarial evidence |
|---|---|---|
| Job-expiry/failure race | Local expiry still accepts the first authenticated completion/failure. Delivered, Failed and Expired jobs all permit a signed review. Job notices never change review status. | Both orders plus expiry → review → failure, both verdicts, replay, and late failure after NotPassed in `RequesterMvpLifecycleTest`; late completion retains NotPassed in `ReviewRecoveryTest`. |
| Wrong pre-binding burns the one-shot answer | A fresh valid mismatched callback is retained, with no verdict or consumption. Owner reset clears only a pending binding and its own unused reservation; exact corrected binding finalizes the retained answer. | Every identity/question/window field, yes/no, expiry attempts, one-shot/no retry, exact body/owner checks, swapped prebound deliveries, finalization after signature expiry, and 200k cold signer gas. |
| Abandoned pending ask cannot close | Owner confirmation no longer depends on requester cooperation. It still requires that exact ask, a passed deadline, no receipt and authenticated offchain terminality evidence. | Exact deadline, nonowner, no expiry flag, stale approval, retry, receipt arriving first and old callback rejection tests. |
| Compromised signer retained answer has no incident response | Each receipt records its verification epoch. Rotate safe authority, explicitly revoke a past epoch with an incident evidence hash, then close affected pending receipts as Unanswered. Revocation blocks confirmation immediately; history and consumption survive. | Both bool values, wrong pre-binding, unauthorized/current/unknown/repeated revocation, normal rotation versus explicit revocation, unchanged finalized NotPassed, closed-ID replay and fresh-key retry. |
| Quoted-but-unspent IMD becomes sweepable | Require exact incoming credit/debit and exact Intake net spend. Any discrepancy rolls back the complete transaction, leaving the caller's funds in their wallet. | Fuzzed partial/zero spends on v1/v2 and both paid calls; balances, allowance, request ID, status and count rollback; sweep cannot take any reverted payment; donations and inexact tokens. |
| Paid requests lack caller maximum | Both paid calls require `userMaxPrice`; the current quote must fit it and the owner ceiling. No old uncapped overload remains. | Owner ceiling raised plus price moved with unlimited wallet allowance; stale caller limit reverts without debit, updated limit succeeds, zero fails and lower quote pays only that quote. |

The new tests are in [`RequesterMvpAudit.t.sol`](../test/RequesterMvpAudit.t.sol). Prior audit proofs,
protocol-vector tests, binding/replay tests and listing/ad escrow tests remain in the full suite.
Older tests were migrated to the required price argument and the deliberately changed timeout/
mismatch-retention semantics; no failure assertions about binding or replay were dropped.

## Compatibility and operating decisions

- The paid selectors changed to `openJob(bytes32,bytes,uint256)` and
  `requestReview(bytes32,uint256)`. Update callers using the full
  [site ABI](../site/HookJobRequester.abi.json) and [API guide](STORE_API.md).
- Constructor inputs and the `Job`, `ReviewAsk` and `ReviewReceipt` read tuples are unchanged.
  Epoch metadata uses previously unused receipt bits. This is immutable source for a future
  deployment, not an upgrade or migration of an existing contract's storage.
- The unsigned Failed status cannot prohibit independent oracle review. Creators should still wait
  for final public review evidence before spending a review fee; the bool question treats missing/
  pending/failed evidence as false, and both finalized verdicts stay terminal.
- Reset is owner-only, explicit and logged. Correct binding still requires independently
  authenticated protocol mapping, never copying the retained fields as their own proof.
- Expiry closure proves no absence of a callback onchain. The owner must establish terminality
  independently; a mistaken owner can still suppress a late answer. An absent owner can delay
  finalization/retries. A requester cannot independently discard a negative receipt.
- Explicit epoch revocation is an owner trust power. It can freeze genuine retained negatives as
  well as forged answers. Retain incident evidence, monitor authority events, and use the agreed
  multisig. Ordinary signer rotation preserves old receipts; explicit revocation prevents their
  confirmation. No operation changes a finalized verdict or clears a consumed UUID.
- Exact spending assumes a non-rebasing, exact-transfer IMD token and an Intake which takes the
  quoted amount. A quote/spend discrepancy reverts atomically instead of creating custody credits.
  There is no refund of a fee actually spent on an accepted request. Ad escrow refunds are separate
  and keep the original payer's entitlement.

## Requires a real IMD Intake test

A separate, explicitly authorized pilot must validate the real job action/body schema and callback
ABI; exact IMD payment and allowance clearing; asynchronous one-shot callbacks and failure evidence;
public job review evidence; authenticated Intake-ID ↔ oracle-UUID mapping and canonical resolved
question/window; timestamp behavior and fresh signing on retries (old signatures predating a new ask by more than 300 seconds are rejected); and actual signer/registry gas under 200k. Local synthetic
mapping hashes and self-signed answers do not establish any of those production properties.
The protocol's independent EIP-712 vector continues to establish struct/domain compatibility.

The [integration guide](IMD_INTEGRATION.md#after-launch) lists constructor inputs, unset templates,
action selection, payment settings, signer qualification and ongoing owner responsibilities.
Advertising still needs the real IMD configuration and approved proceeds recipient before live use.
No addresses, account credentials or operational values were invented for this assignment.
