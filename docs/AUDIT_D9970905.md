The original 126-test coverage remains, with fixture/expectation changes where the fixed behavior
requires them. In particular, a previously generic unrelated attestation no longer settles an ask,
and the previous test forbidding the buyer's cancellation now asserts that cancellation refunds
only the seller. No escrow conservation assertions were removed. The original invariant still
runs; a second suite reuses its assertions and complete wind-down while interleaving listing
transfers and cancellation by current owners.

The protocol attestation layout, type string, domain and callback selector are unchanged. The
independent canonical vector digest is retained, its original signature is verified before its
unsupported non-bool value is rejected, and the vector key signs an accepted bool callback. The
15-word `getJob` ABI and prior event selectors remain intact; `getReviewAsk` and `ReviewBound` are
additions. The static reader includes the new event and preserves its existing reads.

## Compatibility and operational responsibilities

**Review delivery still needs a live pilot.** The supplied protocol reference states that the
Intake ID and signed oracle UUID differ, whereas the audit's minimal equality suggestion assumed
they match. The raw body hash also is not the canonical question hash. This fix does not rely on
either assumption or invent a UUID conversion or canonicalization algorithm.

The chosen bridge is a trusted, one-time owner binding per ask. The owner must authenticate the
Intake-to-oracle mapping, recompute the canonical question hash from that specific body and its
resolved window, then pin the expected fields **before** the one-shot callback. This adds owner
work and availability dependence to each review. A malicious or mistaken owner can bind the wrong
question; signatures cannot correct a wrong trusted expectation. The contract's existing ability
to rotate the signer also means a malicious owner can forge a verdict matching a correct binding.
The integration is not trustless with respect to its owner.

The reference does not establish a pre-delivery mapping endpoint or dispatch coordination. A live
pilot must prove that the owner can obtain these values in time. If it cannot, an authenticated
protocol preflight/mapping facility is needed before production use. An unbound/early callback
reverts and is not retried by the Intake; the requester can expire the ask, but the price is spent.
There is no fallback accepting mismatched IDs or a guessed hash.

Also unresolved: live `job.open` action/body/callback ABI, whether the panel can reliably read the
review outcome, exact canonicalization and relative-window resolution, timestamp ordering,
Intake/oracle ID uniqueness across retries/migrations, gas with the actual signer/registry and
public-chain finality/RPC behavior. EIP-7702 tests reproduce the code-presence regression under
the pinned Cancun runtime; they do not execute a live delegation transaction.

[IMD_INTEGRATION.md](IMD_INTEGRATION.md) documents constructor arguments, per-ask binding, all owner
settings and the pilot procedure. [LISTINGS_AND_ADS.md](LISTINGS_AND_ADS.md) documents token/treasury
configuration, current-owner cancellation and payer refund rights. No launch parameters were
invented. The exact ad proceeds recipient remains an owner-settable value requiring the
requester's operational choice before live use, as before this assignment.

These source fixes are not an upgrade to any deployed immutable contract. Release/deployment,
address verification, independent adversarial review of the changes, owner multisig operation,
binding accuracy/timeliness and monitoring remain the operator's responsibilities.
